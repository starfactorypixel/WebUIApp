## Общая разметка

```html
<ui-element type="value" obj="0x0110" config='{"name":"Скорость", ...}'></ui-element>
```

| Атрибут  | Обязателен | Описание |
|----------|:---:|---|
| `type`   | да  | Тип виджета: `value`, `meter`, `stream`, `cellbalance`, `button`, `radio`, `range`, `livecontrol`. |
| `obj`    | да  | Адрес объекта данных в шестнадцатеричном виде: `0x0110` или `0110`. Для `button`, `radio`, `range` и `livecontrol` можно указать список через запятую: `obj="0x0164,0x0165,0x0166"`. Если список указать другим виджетам, они возьмут первый obj и выведут предупреждение в консоль. |
| `config` | нет | JSON с настройками, `{}` по умолчанию. Атрибут удобно брать в одинарные кавычки, а внутри JSON использовать двойные. |

Виджет на вкладке создаётся при её открытии и уничтожается при закрытии. При этом автоматически уходят подписка и отписка.

Виджеты **вне вкладок** (любой `<ui-element>` не внутри `<div data-tab-title>`, например блок под вкладками) создаются один раз при загрузке страницы и живут, пока она открыта. Оформить такой блок можно теми же классами, что и вкладки:

```html
<div class="tabs">
	<div class="tabs__panel">
		<ui-element type="value" obj="0x0110" config='{…}'></ui-element>
	</div>
</div>
```

Один obj может быть у нескольких виджетов сразу (во вкладке и вне её): пакеты получают все.

## Общие параметры config

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`   | строка | — | Заголовок виджета. Выводится как текст, HTML экранируется. |
| `type`   | строка | — (`uint8` у управляемых виджетов) | Тип значения в пакете: `bool`, `uint8`, `int8`, `uint16`, `int16`, `uint32`, `int32`, `float32`, `float64`. Порядок байт — little-endian. |
| `scale`  | число | `1` | Делитель: `value = value_raw / scale`. Например, `scale: 10` и raw `528` дают `52.8`. |
| `format` | строка | — (`${value}` у `range`) | Шаблон подписи, см. [ниже](#формат-подписи-format). |
| `debug`  | bool | `false` | Отладка: каждый пакет, который **этот** виджет отправил (`→`) и получил (`←`), пишется в [лог](#лог): `[Газ М1+М2] → 0x0104: 0A 05 E5 02`. Работает у любого виджета, в том числе у нового. |

## Формат подписи (format)

Подстановки пишутся как `${имя}` или `${имя:%спецификатор}`. Состав имён зависит от виджета и указан в его разделе. Если значения нет (`null`), подстановка даёт пустую строку.

Спецификатор устроен так: `%[флаг][0][ширина][.точность]тип`

| Часть | Значения | Пример |
|---|---|---|
| флаг | `+` — всегда показывать знак, пробел — пробел вместо `+` | `%+5.1f` → ` +3.2` |
| `0` | дополнять нулями после знака | `%05.1f` → `-03.2` |
| ширина | минимальная длина; по умолчанию дополняется пробелами | `%5d` → `   42` |
| `.точность` | знаков после запятой, только для `f` | `%1.3f` → `3.500` |
| тип | `d` — целое, `f` — дробное, `x`/`X` — hex, `s` — строка | `%X` → `FF` |

Результат вставляется как HTML, поэтому в `format` можно использовать теги, например `"<b>${value}</b> V"`.

Примеры:

```
"Speed: ${value:%02d}Kmh"        → Speed: 100Kmh
"Voltage: ${value:%04.1f}V"      → Voltage: 52.8V
"Current: ${value:%+5.1f}A"      → Current: -10.0A
"${number:%02d}: ${value:%1.3f}V" → 03: 4.000V
```

## Протокол пакетов

Первый байт пакета — всегда **fId**, данные начинаются со второго байта.

**Входящие** (от устройства):

| fId | Значение | Данные |
|---|---|---|
| `0x61` | Периодическая отправка, уровень «норма» | `[0x61, value…]` |
| `0x62` | Периодическая отправка, «предупреждение» | `[0x62, value…]` |
| `0x63` | Периодическая отправка, «критический уровень» | `[0x63, value…]` |
| `0x65` | Текущее (новое) состояние. Приходит в ответ на любую команду и на подписку | `[0x65, value…]` |
| `0xE6` | Ошибка объекта. Пока не обрабатывается отдельно | `[0xE6, …]` |

У `stream` и `cellbalance` формат данных другой — см. их разделы.

**Исходящие** (команды объекту: `{cmd: 'CanMsg', data: [{id: obj, bytes}, …]}`; виджет отправляет через `this.SendCanMsgBatch([...])` базового класса, команда в несколько obj — одним массивом, сервер отправляет её одним пакетом):

| fId | Команда | Данные |
|---|---|---|
| `0x01` | SET — установить значение | `[0x01, value…]` (по `config.type`) |
| `0x02` | TOGGLE — переключить, устройство решает само | `[0x02]` |
| `0x03` | ACTION — однократное действие | `[0x03]` |
| `0x11` | Запрос всех значений `stream` (кнопка ⟳ или автозапрос `interval`) | `[0x11]` |
| `0x0A` | RealTime — значение «живого» управления (`livecontrol`, `mode: "realtime"`), ответа нет | `[0x0A, counter, value…]` |

В ответ на подписку ESP присылает последнее известное состояние объекта (`0x65`), поэтому новый виджет сразу получает данные. Как это устроено между сервером и ESP — `PROTOCOL_SERVER_ESP.md`.

## Виджеты

### value — значение

Отображает число с подписью, при желании с графиком последних значений.

```html
<ui-element type="value" obj="0x0110"
  config='{"name":"Скорость","format":"Speed: ${value:%02d}Kmh","type":"uint16","scale":10,
           "chart":{"count":64,"mode":"fill"}}'></ui-element>

<ui-element type="value" obj="0x0170"
  config='{"name":"IO in 5","format":"In5: ${value:%1.3f}V, ${expr}","type":"uint16","scale":1000,
           "expr":[["<",1.5,"Мало"],[">",3.5,"Много"],["Норма"]]}'></ui-element>
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`, `type`, `scale`, `format` | | | см. [общие параметры](#общие-параметры-config) |
| `chart` | объект | нет | Если задан, под значением рисуется график. |
| `chart.count` | число | `100` | Сколько последних точек хранить и показывать. |
| `chart.mode` | `"line"` \| `"fill"` | `"line"` | Только линия или линия с заливкой. |
| `expr` | массив | нет | Правила для подстановки `${expr}`, см. ниже. |
| `autocolor` | bool | `false` | Раскраска по типу таймера: `0x61` — норма, `0x62` — предупреждение, `0x63` — критично. См. [Раскраска по типу таймера](#раскраска-по-типу-таймера-autocolor). |

**Подстановки в format:** `${value}`, `${value_raw}`, `${expr}`.

**Правила `expr`.** Список проверяется сверху вниз, срабатывает первое подходящее правило. Сравнивается значение после деления на `scale`.

| Вид правила | Смысл |
|---|---|
| `[оператор, порог, "текст"]` | Если `value <оператор> порог`, то `${expr}` = текст. Операторы: `<`, `<=`, `>`, `>=`, `=`, `!=`. |
| `["текст"]` | Без условия, используется как «иначе». Ставится последним. |

**Цвет графика** задаётся fId пакета: `0x61` — зелёная палитра, `0x62` — оранжевая, `0x63` — красная. Пакеты с другим fId (например, `0x65`) палитру не меняют.

Пакет короче, чем нужно для `type`, игнорируется.

### meter — шкала

Стандартный HTML-элемент `<meter>` с подписью значения.

```html
<ui-element type="meter" obj="0x0113"
  config='{"name":"Motor RR voltage","format":"${value:%2.1f}V","type":"uint16","scale":10,
           "min":60.0,"max":84.0,"low":73.0,"high":74.0,"optimum":75.0}'></ui-element>
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`, `type`, `scale`, `format` | | | см. [общие параметры](#общие-параметры-config) |
| `min`, `max` | число | — | Границы шкалы (в единицах после `scale`). |
| `low`, `high` | число | — | Границы «нормальной» зоны. Браузер подкрашивает шкалу. |
| `optimum` | число | — | Оптимальное значение. Определяет, какая зона считается хорошей. |
| `autocolor` | bool | `false` | Раскраска по типу таймера: `0x61` — норма, `0x62` — предупреждение, `0x63` — критично. См. [Раскраска по типу таймера](#раскраска-по-типу-таймера-autocolor). |

**Подстановки в format:** `${value}`, `${value_raw}`.

### stream — набор ячеек

Много однотипных значений с одного obj, например напряжения ячеек АКБ или датчики температуры. Каждый пакет обновляет одну ячейку по её номеру. Ячейки выводятся компактной сеткой по возрастанию номера: в ячейке мелко номер и жирно значение. Ячейка с минимальным значением подсвечивается синим, с максимальным — красным (если значения не все одинаковые).

```html
<ui-element type="stream" obj="0x0190"
  config='{"name":"Ячейки АКБ 1","format":"${value:%1.3f}V","type":"uint16","scale":1000}'></ui-element>

<!-- автозапрос раз в 5 с, без кнопки -->
<ui-element type="stream" obj="0x0194"
  config='{"name":"Температуры АКБ 1","format":"${value:%d}°C","type":"int8","interval":5000}'></ui-element>
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`, `type`, `scale` | | | см. [общие параметры](#общие-параметры-config); `type` относится к значению ячейки |
| `format` | строка | `${value}` | Формат **значения** ячейки. Номер выводится отдельно, в `format` его писать не нужно. |
| `columns` | число | `8` | Ячеек в строке. |
| `interval` | мс | `0` | Автозапрос значений: `[0x11]` сразу при открытии и затем каждые `interval` мс, кнопки нет. `0` или не задан — запрос только вручную кнопкой ⟳ в заголовке. |

**Пакет:** `[fId, number (uint8), value (по type)]`.

**Подстановки в format:** `${value}`, `${value_raw}`, `${number}`.

Автозапрос работает, только пока виджет открыт: при закрытии вкладки таймер останавливается.

### button — кнопка

Управление одним obj или группой. Подробнее о группах — в разделе [Управляемые виджеты](#управляемые-виджеты-группы-obj-и-подтверждение).

```html
<!-- один obj: TOGGLE -->
<ui-element type="button" obj="0x0169"
  config='{"name":"IOut 6","format":"${icon1}[${txt}]","type":"uint8","txt":"255:ON,0:OFF"}'></ui-element>

<!-- группа: SET -->
<ui-element type="button" obj="0x0164,0x0165,0x0166"
  config='{"name":"IOut 1-3","format":"${icon1}[${txt}] ${count}","type":"uint8","txt":"255:ON,0:OFF"}'></ui-element>
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`, `type`, `scale`, `format` | | `type`: `uint8` | см. [общие параметры](#общие-параметры-config) |
| `txt` | строка | нет | Подписи для значений в виде `"значение:текст,…"`, например `"255:ON,0:OFF"`. Используется в `${txt}`; значения не из списка показываются как `-`. |
| `cmd` | `"toggle"` \| `"set"` \| `"action"` | один obj — `toggle`, группа — `set` | Какую команду отправлять по нажатию. |
| `on`, `off` | число | `255`, `0` | Значения для `cmd: "set"` (raw, без `scale`). |
| `timeout` | мс | [глобальный](#глобальные-настройки) | Время ожидания ответа `0x65`. |

**Логика `cmd: "set"`.** Если все obj включены (равны `on`), отправляется `off`. Во всех остальных случаях — `on`: из `off`, из смешанного, из неизвестного состояния. Для группы `toggle` по умолчанию не используется: из смешанного состояния каждый obj переключился бы по отдельности, и группа осталась бы смешанной.

**Подстановки в format:**

| Имя | Значение |
|---|---|
| `${value}` | Общее значение после `scale` (пусто, если значения разные или неизвестны) |
| `${value_raw}` | Общее сырое значение |
| `${icon1}` | ⏳ — ждём ответа, ⚠️ — значения разные, 🟡 — неизвестно, 🔴 — 0, 🟢 — не 0 |
| `${txt}` | Подпись из `txt`; `смеш.` — значения разные; `-` — нет в списке |
| `${count}` | Сколько obj сообщили состояние / всего, например `3/3` |

Пока ждём ответ, кнопка заблокирована.

### radio — переключатель

Выбор одного значения из списка для одного obj или группы.

```html
<ui-element type="radio" obj="0x0106,0x0107"
  config='{"name":"КПП 1+2","radios":"0:N,1:F,2:R,4:L,8:B","type":"uint8"}'></ui-element>
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`, `type` | | `type`: `uint8` | см. [общие параметры](#общие-параметры-config) |
| `radios` | строка | — (обязателен) | Варианты в виде `"значение:подпись,…"`. Значение — raw. |
| `readonly` | bool | `false` | Только отображение, без управления. |
| `timeout` | мс | [глобальный](#глобальные-настройки) | Время ожидания ответа `0x65`. |

**Поведение:**
- Клик не ставит отметку сам. Во все obj уходит SET выбранного значения, а отметка появляется только после подтверждения.
- Пока ждём ответ, выбранный вариант подсвечен (класс `is-target`), а переключатель заблокирован.
- Если у obj группы разные значения, ничего не отмечено, а у виджета оранжевая рамка (`is-mixed`).
- Если пришло значение не из списка, отметка снимается.

`format` не используется.

### range — ползунок

Аналог `<input type="range">` для одного obj или группы.

```html
<ui-element type="range" obj="0x0180"
  config='{"name":"Яркость","format":"${value:%d}%","type":"uint8","min":0,"max":100,"step":5}'></ui-element>

<ui-element type="range" obj="0x0181,0x0182"
  config='{"name":"Уставка 1+2","format":"${value:%1.1f}V","type":"uint8","scale":10,
           "min":0,"max":25.5,"step":0.1}'></ui-element>
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`, `type`, `scale` | | `type`: `uint8` | см. [общие параметры](#общие-параметры-config) |
| `format` | строка | `${value}` | Подпись под ползунком. |
| `min`, `max` | число | `0`, `100` | Границы, в единицах после `scale`. |
| `step` | число | `1` | Шаг, в единицах после `scale`. |
| `readonly` | bool | `false` | Только отображение. |
| `timeout` | мс | [глобальный](#глобальные-настройки) | Время ожидания ответа `0x65`. |

**В устройство уходит** `value × scale`, для целых типов с округлением. Например, 20.0 при `scale: 10` превращается в 200. Следите, чтобы `max × scale` помещался в `type`.

**Подстановки в format:** `${value}`, `${value_raw}`.

**Поведение:**
- Во время перетаскивания меняется только подпись, в сеть ничего не уходит.
- SET уходит по окончании ввода: когда отпустили мышь или палец либо нажали стрелку на клавиатуре.
- Если отпустили, не изменив значение, ничего не отправляется.
- Пока ждём ответ, ползунок стоит на выбранном значении, заблокирован, а подпись начинается с ⏳.
- Ответ совпал — ползунок остаётся. Нет ответа или пришло другое значение — ползунок возвращается к факту, и появляется красная рамка.
- Если у obj группы разные значения, в подписи `смеш.`, а ползунок не двигается.

### livecontrol — ползунок с удержанием

«Живое» управление (газ, руль, джойстик): значение действует, только пока ползунок держат. Для одного obj или группы. Ответов не ждёт и на obj не подписывается — отправка «в пустоту».

```html
<ui-element type="livecontrol" obj="0x0104,0x0105"
  config='{"name":"Газ М1+М2","format":"${value:%d}","type":"uint16",
           "min":0,"max":1023,"default":0,"interval":100,"mode":"realtime"}'></ui-element>
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name`, `type`, `scale` | | | см. [общие параметры](#общие-параметры-config); `type` обязателен |
| `format` | строка | `${value}` | Подпись под ползунком. |
| `min`, `max` | число | `0`, `100` | Границы, в единицах после `scale`. |
| `step` | число | `1` | Шаг, в единицах после `scale`. |
| `default` | число | `min` | Куда ползунок возвращается, когда его отпустили, и что уходит последним пакетом. Не задан — предупреждение в консоли. |
| `interval` | мс | `100` | Как часто, пока держим, отправляется текущее значение. |
| `mode` | строка | `"set"` | `"set"` — пакет `[0x01, value]`; `"realtime"` — `[0x0A, counter, value]`. |
| `readonly` | bool | `false` | Только отображение. |

**Поведение:**
- **Отпущен** — ничего не отправляется, ползунок стоит в `default`.
- **Держим** — сразу и затем каждые `interval` мс текущее значение уходит во все obj. Виджет обведён оранжевой рамкой.
- **Отпустили** — ползунок возвращается в `default`, уходит один пакет с `default`.
- «Отпустили» — это и отпускание мыши или пальца (даже за пределами ползунка), и отпускание клавиши (стрелки тоже держат ползунок), и потеря фокуса, и скрытие страницы, и закрытие вкладки с виджетом: значение не «залипает».

**Пакеты:** все obj — одним WS-сообщением, сервер отправляет их в ESP одним пакетом L3. `value` — по `type`, little-endian, `value × scale` (для целых — с округлением).
- `"set"`: `[0x01, value]` — как SET у `range`.
- `"realtime"`: `[0x0A, counter, value]`. `counter` — uint8, +1 на каждый пакет этому obj (после 255 — 0). Устройство проверяет его только внутри непрерывного потока: что клиент не «залип» и пакеты не перепутались; после паузы больше 3 × interval оно сбрасывает проверку и уходит в безопасный режим, так что новый поток может начинаться с любого значения. В коде счётчик один на obj для всех `livecontrol` страницы — так проще всего и ничего не стоит.

Нет связи с сервером — пакеты просто не уходят (страница при этом серая).

**Подстановки в format:** `${value}`, `${value_raw}`.

### cellbalance — баланс ячеек АКБ

Компактно показывает дисбаланс ячеек: максимальное и минимальное напряжение, номера этих ячеек и разницу между ними.

```html
<ui-element type="cellbalance" obj="0x018E" config='{"name":"Баланс АКБ 1","autocolor":true,"range":[2.8,4.2]}'></ui-element>
```

```
▲ #11   3.390 V      ← максимум и номер ячейки
▼ #4    3.100 V      ← минимум и номер ячейки
Δ        290 mV      ← разница max − min
[   ▬▬▬▬       ]     ← где min..max внутри range (если задан)
```

**Пакет** (7 байт, little-endian):

```c
struct { uint8_t fId; uint16_t val[2]; uint8_t num[2]; };
//       val[0] = min, val[1] = max;  num[0] = № ячейки min, num[1] = № ячейки max
```

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | строка | — | Заголовок. |
| `scale` | число | `1000` | Делитель для `val`: raw в мВ → вольты. |
| `format` | строка | `${value:%1.3f} V` | Формат min и max. Подстановки: `${value}`, `${value_raw}`. |
| `range` | `[мин, макс]` | нет | Рабочий диапазон напряжения ячейки, например `[2.8, 4.2]`. Если задан, под значениями рисуется полоска с отрезком min..max. |
| `autocolor` | bool | `false` | Раскраска по типу таймера (наихудшее значение); отрезок на полоске окрашивается в тот же цвет. См. [Раскраска по типу таймера](#раскраска-по-типу-таймера-autocolor). |

Дельта всегда выводится в мВ: `(max − min) / scale × 1000`.

Тип таймера (`0x61`/`0x62`/`0x63`) устройство выставляет по наихудшему значению. Пакет `0x65` приходит без него.

---

### Раскраска по типу таймера (autocolor)

Индикаторные пакеты приходят по одному из трёх таймеров, и тип таймера в fId уже классифицирует значение. С `"autocolor": true` виджет раскрашивается по нему полосой слева:

| fId | Тип таймера | Класс на `<ui-element>` | Вид |
|---|---|---|---|
| `0x61` | норма | `color-normal` | зелёная полоса |
| `0x62` | предупреждение | `color-warning` | оранжевая полоса |
| `0x63` | критично | `color-critical` | красная полоса и розовый фон |

- Работает в `value`, `meter` и `cellbalance`. По умолчанию выключено; если параметра нет — тоже выключено.
- Пакет `0x65` (ответ на чей-то запрос) приходит без типа таймера: значение обновляется, цвет остаётся прежним.
- В своём виджете: `if(this.config.autocolor) this.AutoColor(fId);` — метод из `UIWidget`, соответствие fId → тип берётся из `this.timer_type`.

```html
<ui-element type="value" obj="0x0192" config='{"name":"Макс. темп. АКБ 1","autocolor":true,"format":"${value:%d}°C","type":"int8"}'></ui-element>
```

## Управляемые виджеты: группы obj и подтверждение

Относится к `button`, `radio` и `range`.

**Отправка.** Команда уходит во все obj виджета одним WS-сообщением, сервер отправляет её в ESP одним пакетом. Повтора нет: если что-то не так, это показывается, а решение остаётся за пользователем. Пока ждём ответ, виджет заблокирован.

**Подтверждение.** Нужен ответ `0x65` от каждого obj:
- для SET значение в ответе должно совпасть с отправленным;
- для TOGGLE и ACTION подходит любой ответ `0x65`.

Логика целиком лежит в `js/client/control.js` (класс `Control`). Состояние, которое видит виджет:

| Поле | Что значит |
|---|---|
| `value` | Общее значение всех obj. `null`, если кто-то ещё не сообщил значение или значения разные. |
| `mixed` | `true`, если obj сообщили разные значения. |
| `busy` | `true`, пока ждём ответ на команду. |
| `target` | Значение, отправленное последним SET. |
| `failed` | obj, не подтвердившие последнюю команду: не ответили за `timeout`, ответили не тем значением или команда не ушла из-за отсутствия связи. Очищается следующей командой. |
| `values` | Последнее значение каждого obj по отдельности. |

**Подсказка.** При наведении на виджет с ошибкой видно, какие obj не подтвердили команду.

**Лог отклонений.** Когда команда завершилась (ответили все или вышло время) и что-то пошло не так, в [лог](#лог) пишется одна строка: имя виджета, команда и что фактически ответил каждый obj. Отклонением считается:
- obj не ответил за `timeout` (`нет ответа`) или команда не ушла из-за отсутствия связи (`не отправлено`);
- на SET obj ответил другим значением;
- у группы ответы разные, например TOGGLE развёл obj в разные состояния.

Значения в строке сырые (raw, без `scale`). Примеры:

```
[Рекуперация М1+М2] SET 0: 0x0108=0, 0x0109=нет ответа
[КПП М1+М2] SET 8: 0x0106=8, 0x0107=4
[Выход 2] TOGGLE: 0x0165=нет ответа
[Выход 1] TOGGLE: 0x0164=не отправлено
```

Успешные команды в лог не пишутся.

## CSS-классы состояния

Классы ставятся на элемент `<ui-element>`.

| Класс | Когда |
|---|---|
| `is-mixed` | значения obj различаются |
| `is-pending` | ждём ответ на команду |
| `is-failed` | команда не подтверждена |
| `is-target` | на `<label>` варианта radio, который ожидает подтверждения |
| `is-active` | `livecontrol`: ползунок держат, значения уходят в устройство |
| `color-normal` / `color-warning` / `color-critical` | `autocolor`: тип таймера последнего пакета |

На `<html>` ставится `ws-online` или `ws-offline` — признак связи с сервером. По умолчанию без связи виджеты становятся серыми и полупрозрачными.

## Лог

Модуль `js/utils/loghtml.js` — общий лог браузерной части для всей системы. Строка выводится на страницу (в `<div id="log">`, если он есть) и в консоль браузера.

```js
import { log } from '../../utils/loghtml.js';   // путь от js/client/widgets/

log.info('[WS] Соединение установлено');
log.warn('[Газ М1+М2] SET 700: 0x0104=700, 0x0105=нет ответа');
log.error('[Виджеты] Некорректный JSON в config', el, err);
```

- Первый аргумент — текст, он попадает на страницу с временем `ЧЧ:ММ:СС`.
- Остальные аргументы (DOM-элементы, ошибки, объекты) уходят только в консоль, там их удобно раскрыть.
- На странице хранятся последние 200 строк (`LOG_MAX_LINES`).
- Уровни отличаются цветом: строкам ставятся классы `log_info`, `log_warn`, `log_error` (см. `client.css`).

**Что куда пишется.** Правило: на экран — то, что важно пользователю; ошибки настройки виджетов — только в консоль (для того, кто настраивает).

| Куда | Что |
|---|---|
| Экран + консоль (`log.*`) | Соединение и переподключение (`[WS]`), команда не отправлена из-за отсутствия связи, переключение вкладок (`[Вкладки]`), ошибки обработки пакетов (`[Пакеты]`), отклонения управляемых виджетов (`[имя виджета]`), пакеты виджетов с `"debug": true` (`log.packet`) |
| Только консоль (`console.*`) | Ошибки разметки и config виджетов (`[Виджеты]`: неизвестный тип, неверный `obj`, битый JSON, ошибки `Render`/`Destroy`), неизвестный оператор в `expr` |

## Глобальные настройки

В `js/app-client.js`:

| Настройка | По умолчанию | Описание |
|---|---|---|
| `Control.timeout` | `1100` | Время ожидания ответа на команду, мс. У отдельного виджета переопределяется через `config.timeout`. |

## Свой виджет

1. Создать `js/client/widgets/xxx.js` с классом-наследником `UIWidget`, указать в нём `static type = 'xxx'`, а при поддержке нескольких obj — `static multiObj = true`.
2. **Отправлять пакеты только через `this.SendCanMsgBatch([{ id, bytes }, ...])`** базового класса, а не через `ws.js` напрямую: иначе у виджета не будет работать `debug`. Всё, что относится к одному действию, — одним вызовом (один пакет L3).
3. В `Render()` построить HTML и явно подписаться: `this.Subscribe()` подписывает на свой obj с обработчиком `Update(data, id)`, `this.Subscribe(id, handler)` — на любой obj со своим обработчиком.
4. Переопределять `Destroy()` нужно, только если есть свои ресурсы. Обязательно вызвать `super.Destroy()` — он снимает все подписки.
5. Для управляемых виджетов использовать `Control` из `js/client/control.js`, как в `button.js`, `radio.js` и `range.js`. Шаблон:
   - в `Render()`: `this.control = new Control(this.ids, this.config, () => this.Show());`, подписаться на каждый obj и вызвать `this.Show()`;
   - в `Update(data, id)`: `this.control.onPacket(id, data);`;
   - по действию пользователя: `this.control.set(value)`, `toggle()` или `action()`;
   - в `Show()`: отрисовать `control.value` / `busy` / `mixed` и вызвать `this.control.showState(this.element)`;
   - в `Destroy()`: `this.control.destroy(); super.Destroy();`.
6. Зарегистрировать класс одной строкой в `js/app-client.js`.
